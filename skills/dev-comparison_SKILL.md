# Сравнительный анализ в разработке

Протокол выбирается, когда задача допускает НЕСКОЛЬКО вариантов
(библиотека, метод, стек, подход к задаче). Для факта/единственной
команды сравнение НЕ запускается (перегрузка — антипаттерн).

## Уровни активации

| Уровень | Когда | Что выдаём |
|---|---|---|
| 1 | Небольшой выбор (функция/небольшая библиотека) | Краткая таблица + вывод |
| 2 | Средний (библиотека/фреймворк/подход для задачи) | Таблица + условия выбора |
| 3 | Архитектурный (стек для проекта) | Полный бенчмаркинг + формула |

## Алгоритм

1. Выпиши реальные варианты (от 2 до 5, не раздувай).
2. Определи критерии под ЗАДАЧУ: простота, сопровождаемость, производит.
   (только если критично), сообщество/актуальность, лицензия, обучение
   (новичку/¬новичку), интеграция с текущим стеком.
3. Сравни в таблице (по 3–7 критериев, максимум).
4. Найди ЛУЧШУЮ ФОРМУЛУ под условия пользователя + условия альтернативы.
5. Проверь актуальность версий (dev-registry) — не выдумывай.

## Формат ответа (уровень 2–3)

```
### Варианты: A / B / C
| Критерий | A | B | C | примечание |
| ... |
### Лучшая формула
При условиях [конкретные условия задачи] → **B** ([короткое обоснование]).
### Альтернатива
Если [условие меняется: новичок / меньше зависимостей / ...] → **A**.
### Не выбирай сейчас
C — из-за [причина], мониторить при [что изменится].
```

## База лучших формул (Memory-of-Thought)

Лучшие решения записываются в MCP memory (сущность с полем solution).
Каждая запись: контекст задачи, формула, почему победила, альтернатива.
При похожем запросе — сначала проверить базу (search), потом строить новую.

Примеры (хранить в памяти, не дублировать тут деталями):
- Парсинг HTML на Python: BeautifulSoup (лёгкое) / Playwright (JS-рендеринг).
- CLI на Python: argparse (штатно) / typer/click (удобнее для многих команд).
- Excel на Python: openpyxl (xlsx без Excel) / pandas (данные/аналитика).
- Управление Python: uv (уже установлен, держит версии и venv).

## Антипаттерны анализа

| Антипаттерн | Вместо |
|---|---|
| Сравнение ради сравнения | сравнивать только если есть выбор |
| Таблица на 10 критериев на простой вопрос | 2–3 критерия, кратко |
| «Самый популярный» без условий | формула под задачу + альтернатива |
| Выдуманные версии/зависимости | проверка (pip/README) |
| Выбор без учёта опыта пользователя | учить / боевой проект — разные формулы |

## Применение

Любой выбор технологии/инструмента/подхода → этот протокол (кроме явных
«у нас уже такой стек»). После решения — записать формулу в memory.
