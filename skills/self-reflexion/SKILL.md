# Самоанализ, тесты и авторегенерация промта

Активируется ТОЛЬКО по прямому запросу пользователя: «тест учителя»,
«прогон», «самоанализ», «доработай промт», «улучши промт», «рефлексия»,
«meta», «регрессия», «обнови ссылки» — или после серии из 5+ сложных
запросов с предложением провести самоанализ. В обычных ответах этот
скил не задействуется.

## Этап 1. Самоанализ работы (Reflexion + Self-Critique + MARS)

Проведи рефлексию по схеме и выведи пользователю:

=== САМОАНАЛИЗ ===

1. КАЧЕСТВО ОТВЕТОВ
   - Соответствие нормативной базе: [полное / частичное / с оговорками]
   - Полнота: [достаточно / не хватает ...]
   - Точность формулировок: [высокая / средняя / требует правок]
   - Соответствие формату запроса: [да / нет, потому что ...]
   - Актуальность ссылок: [все актуальны / устарели: ...]
   - Качество сравнительного анализа: [полный / краткий / не нужен]

2. ОШИБКИ И РИСКИ
   - Что могло пойти не так: [перечисли]
   - Какие допущения были сделаны: [перечисли]
   - Какие нормативные документы могли измениться: [укажи]
   - Какие ссылки могли устареть: [укажи]

3. ОЦЕНКА ПО 8 КРИТЕРИЯМ (1–10)
   - Нормативная точность: X/10
   - Методическая ценность: X/10
   - Практическая применимость: X/10
   - Сравнительный анализ: X/10
   - Форматное соответствие: X/10
   - Полнота ответа: X/10
   - Актуальность ссылок: X/10
   - Соответствие СанПиН: X/10
   - Средний балл: X/10

4. ПРОТОКОЛ ПРОВЕРОК: СТАТУС (скил quality-checks)
   - Группа A (нормативные): [X из 10]
   - Группа B (методические): [X из 6]
   - Группа C (СанПиН): [X из 7]
   - Группа D (ЭОР): [X из 4]
   - Группа E (фактологические): [X из 4]
   - Группа F (форматные): [X из 5]
   - Группа G (сравнительный анализ): [X из 5]
   - Всего: [X из 41]

5. ЗОНЫ РОСТА
   - Что улучшить в следующий раз: [перечисли]
   - Какие техники промт-инжинерии дали наибольший эффект: [перечисли]
   - Какие техники стоит добавить: [перечисли]
   - Какие проверки сработали лучше всего: [перечисли]
   - Какие проверки не сработали: [перечисли]
   - Сработал ли сравнительный анализ: [да / нет / почему]

6. MARS: МЕТАКОГНИТИВНАЯ РЕФЛЕКСИЯ
   - Принципы, извлечённые из этой сессии (что избегать): [перечисли]
   - Процедуры, приведшие к успеху (что воспроизвести): [перечисли]
   - Новые лучшие формулы, добавленные в базу (metod-comparison): [перечисли]

7. BUFFER OF THOUGHTS: НАКОПЛЕННЫЕ ИНСАЙТЫ
   - Повторяющиеся паттерны в запросах: [перечисли]
   - Типичные дефициты данных: [перечисли]
   - Сильные стороны текущего промта: [перечисли]
   - Слабые места текущего промта: [перечисли]
   - Обнаружены ли устаревшие ссылки: [да/нет, какие]
   - Обнаружены ли новые приказы: [да/нет, какие]

## Протокол прогона тестов (команда «тест учителя» / «прогон»)

Выполняется в СВЕЖЕЙ сессии (чистый контекст) — это строгий замер.
Одна сессия = один прогон. Шаги:

1. Найди файлы плана тестирования: `01_разбор\план_тестирования.md`
   и `01_разбор\тест_ПРОГОН.md` в текущем проекте (где установлен
   комплект). Если файлов нет — создай их по этому скилу: 6 контрольных
   запросов по ключевым скилам и чек-лист из 12 пунктов.
2. Прочитай контрольные запросы (6 шт.) и чек-лист (12 пунктов).
3. Зафиксируй хэши промта и скилов (SHA-256) — сверь с отчётом.
4. Выполни 6 запросов ПОДРЯД: для каждого сформулируй ответ по протоколу
   промта (5 шагов мышления, скилы по вызову, чек-лист в конце).
   Вопросы можно варьировать по форме, но НЕ по смыслу.
5. Оцени каждый ответ по чек-листу: 1 балл за пункт, макс. 12.
6. Порог приёмки: **все запросы ≥ 11/12**. Провал → найди причину
   (промт/скил/MCP/исполнение), исправь, перепрогони только этот сценарий,
   затем общую регрессию.
7. Запиши результат в `01_разбор\ОТЧЁТ_ТЕСТ.md` текущего проекта (таблица
   «запрос → балл → замечания»), обнови хэши и дату.
8. Выдай пользователю сводку: баллы по 6 запросам, порог, вывод.

## Журнал ошибок, анти-зацикливание и уборка мусора

### Журнал ошибок (ЖУРНАЛ_ОШИБОК.md)
- Файл: `01_учитель\ЖУРНАЛ_ОШИБОК.md` (в текущем проекте).
- Фиксация: заметил свою ошибку по ходу работы (повтор, неверная команда,
  потеря контекста, зацикливание, мусор) — запиши сразу: ошибка, где,
  причина (промт/скил/исполнение/контекст), статус (открыта/устранена).
- Проверка: при «самоанализ» / «тест учителя» / «прогон» — прочитай
  журнал, проверь статусы, предложи устранение (правка промта/скила),
  закрой устранённые, зафиксируй результат в ЖУРНАЛ.md.
- Автономность: журнал лежит в подпроекте — работает при передаче
  только учителя (у разработчика — свой журнал).

### Анти-зацикливание
- Детекция: 3+ одинаковых попытки / шаг без прогресса / повтор уже
  сказанного.
- Действие: остановись, выведи чек-поинт («сделано X, застрял на Y»),
  спроси пользователя. Не повторяй блок без новой информации.

### Уборка мусора
- После завершения задачи проверь и удали временные файлы, черновики,
  журналы задач, тестовые артефакты — если они не нужны пользователю.
- Включено в quality-checks (проверка F6).

## Правила авторегенерации

1. Вноси только содержательные изменения, не переписывай промт ради
   переформулировок.
2. Каждое изменение сопровождай обоснованием.
3. Веди нумерацию версий: v5.0 → v5.1 → v5.2 и т. д.
4. Сохраняй структуру блоков и совместимость с предыдущими версиями.
5. **Обновляй ссылки** на нормативные документы, если обнаружишь
   устаревшие. Сверяйся со скилом norma-rf.
6. **Обновляй регистр актуальности** (norma-rf) при обнаружении новых
   изменяющих приказов.
7. Добавляй новые техники промт-инжинерии по мере их появления,
   с пометкой в журнале изменений.
8. Если изменений нет — прямо скажи: «Промт актуален, изменений
   не требуется».
9. Удаляй техники, которые не дали эффекта (по итогам самоанализа),
   с пометкой в журнале.
10. Увеличивай количество few-shot примеров, если обнаружил повторяющиеся
    паттерны запросов, не охваченные шаблонами (lesson-templates).
11. При авторегенерации проверяй: не нарушены ли гвардрайлы
    (guardrails-rf), не появились ли устаревшие ссылки, не потеряны ли
    ключевые требования ФГОС/СанПиН.
12. **Проверяй все 41+ проверок из скила quality-checks** при
    авторегенерации.
13. **Обновляй дату в шапке промта** при каждой авторегенерации.
14. **Проверяй срок действия СанПиН** — если истёк, обнови ссылку
    на новый документ.
15. **Пополняй базу лучших формул** (metod-comparison) при обнаружении
    новых эффективных комбинаций методов.
16. **Проверяй метрики** бенчмаркинга: все ли выше 7/10?
17. Сохраняй формат: один блок ``` для копирования.
18. **Проверяй гибкость и простоту**: не перегружен ли промт? Если
    Complexity > 7/10 — упрощай.
19. **Перед выпуском/сдачей версии — регрессионный прогон**: прогнать
    6 контрольных запросов из плана тестирования текущего проекта по чек-листу
    12 пунктов; порог приёмки ≥ 11/12. Любая правка промта, меняющая
    блоки или арсенал скилов, должна подтверждаться регрессией.
    Правило 20. после релиза: раз в 2–4 недели повторный регресс —
    деградация от дрейфа модели должна ловиться планово, а не по факту.
20. **Проверяй ЖУРНАЛ_ОШИБОК.md** при самоанализе/авторегенерации:
    открытые ошибки → предложи устранение, устранённые → закрой.

## Метрики для авторегенерации (бенчмаркинг)

1. **Coverage** — какой процент запросов типов задач промт обрабатывает
   качественно?
2. **Accuracy** — процент нормативно точных ответов?
3. **Flexibility** — насколько промт адаптируется под разный уровень
   сложности запроса?
4. **Simplicity** — не перегружен ли промт? Достаточно ли прост для
   понимания модели?
5. **Comparison quality** — насколько хорошо работает блок сравнительного
   анализа (metod-comparison)?

Если метрика ниже 7/10 — доработай соответствующий блок.

## Критерии оценки ответа (1–10) для самоанализа

| Критерий | 1-3 (низкий) | 4-7 (средний) | 8-10 (высокий) |
|---|---|---|---|
| Нормативная точность | Ошибки в реквизитах | Реквизиты верны, нет ссылок | Реквизиты + ссылки + редакции |
| Методическая ценность | Типовое решение | Обоснованный выбор | Инновационное + обоснованное |
| Практическая применимость | Сложно внедрить | Внедримо с доработкой | Готово к использованию |
| Сравнительный анализ | Нет сравнения | Краткое сравнение | Полный бенчмаркинг + лучшая формула |
| Форматное соответствие | Не соответствует | Частично | Полное |
| Актуальность ссылок | Устаревшие | Актуальные, без проверки | Дуальные ссылки + проверка |
| Полнота ответа | Пробелы | Достаточно | Полно + риски + продолжение |
