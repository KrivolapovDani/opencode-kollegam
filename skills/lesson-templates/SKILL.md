# Шаблоны ожидаемых ответов

Следуй этим паттернам при форматных запросах. Шаблоны демонстрируют
структуру, наполнение — под конкретную задачу.

## Шаблон 1: Запрос данных перед работой

Пользователь: «Составь рабочую программу по математике, 5 класс.»

Ответ:
«Готовлю рабочую программу по математике для 5 класса. Чтобы собрать
её корректно по шаблону Конструктора, уточните:

1. Сколько часов в неделю / в год по учебному плану школы?
2. Какой УМК используется? (Виленкин / Никольский / Дорофеев / другой)
3. Есть ли обучающиеся с ОВЗ? Нужна ли адаптация?
4. Есть ли особые требования в Положении о рабочих программах вашей школы?
5. Какие формы текущего контроля приняты в школе?
6. Как учитывается рабочая программа воспитания школы (раздел ФОП ООО)?
   В Части 1 (пояснительная записка) обязательно укажи: «Программа
   разработана с учётом рабочей программы воспитания школы» — это
   закрывает пункт B4 протокола quality-checks.

Как только получу ответы — выдам полную программу с тремя разделами по
ФГОС, тематическим планированием, учётом программы воспитания и
верифицированными ЭОР.»

**Нормативная база:** ФГОС ООО (приказ №287 от 31.05.2021, ред. 18.06.2025);
ФОП ООО (приказ №370 от 18.05.2023, с изменениями №704 от 09.10.2024
и №808 от 10.11.2025).

  приказа №551 от 23.07.2025.

## Шаблон 3: Сравнительный анализ (уровень 2) — краткая структура

Пользователь: «Какой метод выбрать для урока природоведения в 5 классе
по теме "Свойства воды"?»

Ответ:
«Для темы "Свойства воды" в 5 классе сравню 3 подхода:

| Подход | ФГОС | СанПиН | Эффективность | Возраст | Реализуемость |
|---|---|---|---|---|---|
| А: Демонстрационный эксперимент | + | + | Высокая | Идеально | Нужен лабораторный комплект |
| Б: Виртуальная лаборатория (ЦОК) | + | + | Средняя | Хорошо | Нужен экран/проектор |
| В: Problem-based learning | + | + | Высокая | Хорошо | Требует подготовки |

**Лучшая формула:** A + Б (гибрид). Сначала — реальный эксперимент с водой
(наблюдение свойств), затем — виртуальная лаборатория ЦОК для закрепления
и расширения (недоступные в классе опыты).

**Почему:** 5-классникам важен сенсорный опыт (тактильный, визуальный),
который даёт только реальный эксперимент (А). Виртуальная лаборатория (Б)
дополняет опытом, недоступным в условиях класса. Гибрид обеспечивает
оба канала восприятия.

**Альтернатива:** если нет лабораторного оборудования — подход Б (только
ЦОК) + проблемная ситуация через видеофрагмент РЭШ. Эффективность ниже
на ~20%, но реализуема в любом классе.»

## Шаблон 4: Подсветка рисков с актуализацией

**Риски по теме:**
- Сокращение содержания ниже ФРП — рабочая программа не пройдёт согласование.
- Использование коммерческих ЭОР вместо верифицированных — нарушение
  приказа №551 от 23.07.2025.
- Игнорирование изменений приказа №808 от 10.11.2025 — с 01.09.2026
  вводится предмет «Духовно-нравственная культура России» в ООО.

**Что проверить перед сдачей:**
1. Соответствие содержания ФРП (не ниже минимума).
2. Все ЭОР — из федерального перечня (приказ №551).
3. Три раздела ФГОС заполнены полностью.
4. Часы тематического планирования сходятся с учебным планом.
5. Актуальность редакций ФГОС/ФОП — проверить по верификационным ссылкам
   (скил norma-rf).
6. Учтена ли рабочая программа воспитания школы (B4 quality-checks) —
   упоминание в пояснительной записке обязательно.

**Проверить актуальность:**
- ФГОС: https://docs.cntd.ru/document/607175848
- ФОП: https://edsoo.ru/normativnye-dokumenty/
- СанПиН: https://normativ.kontur.ru/document?moduleId=9&documentId=500088

## Шаблон 5: Работа блоками (антидеградация контекста)

Применяй при БОЛЬШИХ результатах (рабочая программа на год, КТП, пакет
документов), чтобы не терять качество и не проваливать контекст.

### Правила блочной работы

0. **ТЗ (обязательно для больших документов).** Перед стартом сформулируй
   краткое ТЗ: цель, вход/выход, ограничения, список блоков с целями.
   Покажи его пользователю.
1. **Один смысловой блок = один ответ.** Не выдавай весь документ сразу,
   если он больше ~2-3 страниц текста. Разбей на блоки: «Часть 1 из N —
   пояснительная записка», «Часть 2 из N — тематическое планирование»...
2. **Цели блоков.** Каждый блок = один смысловой шаг с измеримой целью
   («готово: X»). Не смешивай цели в одном блоке.
3. **Промежуточные данные не теряй.** Если идёт многоэтапная задача —
   в конце каждого блока кратко фиксируй: «Готово: ... Впереди: ...»
   (чек-поинты = журнал задачи).
4. **Команда «продолжи».** Если пользователь пишет «продолжай /
   продолжи» — сначала повтори краткий чек-поинт (что сделано, что
   дальше), затем выдай следующий блок. Не переспрашивай то, что уже
   известно. Если контекст обрывается — переспроси только недостающий
   чек-поинт.
5. **Новая сессия** — восстанавливай состояние: «Начинаем заново. По
   памяти: сделано ..., осталось ...». Опирайся на MCP memory
   (knowledge-graph), если там есть база формул/наблюдений.
6. **Запрос сам по себе больше одного смыслового шага** → предложи
   план блоков и спроси, с какого начать, ИЛИ выдай первый блок сразу.
7. **Качество не теряй на стыках:** перед выдачей финального блока
   прогони весь собранный результат через quality-checks (внутри блока —
   проверка: «все ли части собраны, не дублируются ли пункты»).
8. **Журнал задачи.** Чек-поинты = журнал задачи. Значимые работы
   (правки промта/скилов) дополнительно фиксируются в ЖУРНАЛ.md проекта.
   Для задач >5 блоков — временный файл `журнал_задачи.md`; по завершении
   удали его (уборка мусора).
9. **Анти-зацикливание.** Заметил повтор (3+ одинаковых попытки, шаг без
   прогресса) — остановись, выведи чек-поинт («сделано X, застрял на Y»),
   спроси пользователя. Не повторяй блок без новой информации.

### Пример чек-поинта в конце блока

«Часть 3 из 5: тематическое планирование — готово (34 строки, часы
сходятся с планом). Впереди: критерии оценивания, список ЭОР, титул.
Продолжить с части 4? Или нужна новая сессия — скажите "заново".»

### Риски блочной работы

- Потерять часть незавершённого документа (дублировать в чек-поинте
  нумерацию: «Часть X из N»).
- «Усыхание» качества к концу длинного ответа — разбивай заранее, а не
  когда контекст уже исчерпан.
- Забыть нормативную базу между блоками — перечитай norma-rf перед
  каждым блоком с документами.

## Применение

- Шаблон 1 — запрос данных перед работой (уточняющие вопросы).
- Шаблон 2 — план урока (таблица «Этап / Время / Учитель / Ученики / Оборудование»).
- Шаблон 3 — сравнительный анализ при выборе метода.
- Шаблон 4 — риски и типичные ошибки + что проверить перед сдачей.
- Шаблон 5 — блочная работа: большие документы, «продолжи», новая сессия.
