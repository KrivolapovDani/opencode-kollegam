# Передача проекта коллеге — чек-лист установки

Этот пакет переносит на другую машину готовый агент «Разработчик»:
лёгкий промт v1.1 + 6 dev-скилов + MCP-серверы. Всё — за 15–20 минут.

## Что в пакете

```
04_коллегам\
  00_ЧЕК_ЛИСТ_УСТАНОВКИ.md   <- этот файл
  РЕЗЮМЕ.md                  <- резюме пакета (что это и как устроено)
  РЕЛИЗ_СООБЩЕНИЕ.md         <- релизное сообщение для передачи
  СВОДКА_ХЭШЕЙ.md            <- SHA-256 всех файлов (проверка целостности)
  v1_промт.md                <- системный промт (для ручной вставки)
  prompts\dev.txt            <- то же самое, но для автоподключения агентом
  03_скилы\                  <- 6 папок со SKILL.md
  opencode_developer.jsonc   <- готовый блок конфига (agent.developer + mcp)
  01_план\                   <- план тестирования, отчёт прогонов, протокол
  ЖУРНАЛ.md                  <- журнал изменений подпроекта
  ЖУРНАЛ_ОШИБОК.md           <- журнал ошибок (фиксация + устранение)
  00_РЕЕСТР_СКИЛОВ.md        <- реестр скилов (версии + changelog)
```

Полную версию проекта с реестром скилов и правилами смотри в родительской
папке `проект промт\` (подпроект `02_разработчик`).

## Шаг 1. Скопируй скилы (2 минуты)

1. Скопируй папку `03_скилы\` целиком в глобальную папку opencode:
   `%USERPROFILE%\.config\opencode\skills\`
   (тогда `skills.paths` в конфиге не нужен / можно не трогать).
2. Итог должен выглядеть так:

   ```
   C:\Users\ИМЯ\.config\opencode\skills\
       dev-checks\SKILL.md
       dev-comparison\SKILL.md
       dev-guardrails\SKILL.md
       dev-reflexion\SKILL.md
       dev-registry\SKILL.md
       dev-templates\SKILL.md
   ```

3. Проверка: запусти opencode и просто напиши «открой скил dev-registry» —
   ассистент должен его распознать.

## Шаг 2. Подключи скилы и MCP в конфиге (10 минут)

1. Открой `opencode.json` / `opencode.jsonc` (создай в корне проекта,
   если его нет).
2. Скопируй блоки `agent`, `skills.paths` и `mcp` из
   `opencode_developer.jsonc`, заменив `ИМЯ_ПОЛЬЗОВАТЕЛЯ` на своё.
3. MCP-серверы:
   - `memory` и `sequential-thinking` — Node.js + npx (уже есть, если
     установлен opencode). Проверка после перезапуска: `/mcp` показывает
     сервер живым.
   - `memory` ПОМНИТ базу формул через файл `memory.jsonl` (переменная
     `MEMORY_FILE_PATH` в конфиге уже прописана). Не удаляй этот файл —
     иначе потеряется история формул между сессиями.
   - `fetch` и `time` — это **Python-пакеты**, в npm их НЕТ. Если нет
     Python/uv — поставь uv одной командой:
     `winget install --id astral-sh.uv -e`, затем
     `uv tool install mcp-server-fetch` и `uv tool install mcp-server-time`
     (поставят exe в `%USERPROFILE%\.local\bin`).

## ВАЖНО: v1.1 работает ТОЛЬКО в opencode

Промт v1.1 — «облегчённый»: реестр инструментов, гвардрайлы, шаблоны,
сравнение и проверки живут в скилах, которые opencode подгружает сам.
**Если вставить v1.1 в другого ассистента (без скилов и MCP) — качество
резко деградирует** (не будет точных версий, запретов, шаблонов,
сравнительного анализа). Для других инструментов добавляй скилы вручную.
Проверка работоспособности — Шаг 4.

## Шаг 3. Активируй агента developer (1 минута, БЕЗ вставки)

Промт подключается автоматически через агента `developer` (блок `agent`
в конфиге уже прописан, промт берётся из `prompts\dev.txt`).

1. Положи папку проекта в удобное место (папок не теряй структуру:
   `opencode_developer.jsonc` и `prompts\dev.txt` должны лежать рядом).
2. Вставь конфиг в `opencode.json`/`opencode.jsonc` (или глобальный
   `~/.config/opencode/opencode.jsonc`, тогда агент будет во всех проектах).
3. Перезапусти opencode, затем в чате переключись на агента:
   - нажми **Tab** (циклический перебор первичных агентов), либо
   - введи `@developer` (если настроен как субагент).
4. Проверка: агент должен ответить короткой фразой готовности по протоколу
   v1.1 (БЛОК 8), не перечисляя функций.

> Ручная вставка остаётся как запасной вариант: если не хочешь агента,
> скопируй содержимое `v1_промт.md` в системный промт вручную.

## Шаг 4. Проверь (3 минуты)

Дай ассистенту три контрольных запроса:

1. «Напиши скрипт Python, который переносит файлы из одной папки в другую
   по шаблону имени с логированием и обработкой ошибок» — должен уточнить
   данные (пути, шаблон, что с дубликатами), а не выдумывать.
2. «Какую библиотеку выбрать для работы с таблицами Excel на Python?» —
   должен провести сравнительный анализ (dev-comparison), а не дать
   один ответ.
3. «тест разработчика» — должен запустить протокол прогона тестов
   (dev-reflexion), а не отказать.

Хороший признак: в ответах появляются точные версии инструментов
(Python 3.13, uv, PowerShell 5.1) и ссылки на документацию.

## Шаг 5. Проверь работу блоками (2 минуты)

Даже рабочий промт «деградирует» в длинных сессиях. Памятка:

1. Большой результат (проект целиком, рефакторинг) — ассистент выдаёт
   блоками «Часть 1 из N ... Часть N из N» и в конце блока пишет чек-поинт
   (что готово / что дальше).
2. Напиши «продолжи» — ассистент должен кратко повторить чек-поинт и
   выдать следующий блок. Если вместо этого он переспрашивает «о чём
   задача?» — контекст не подхвачен: прочитай Шаблон 5 (dev-templates).
3. При «заново» (новая сессия) — ассистент восстанавливает состояние из
   памяти (memory MCP). Если история пропала — проверь `memory.jsonl`.
4. В конце длинной задачи прогони «самоанализ» — dev-reflexion даст
   самоанализ и подскажет, где сессия просела.
5. Ошибки агента фиксируются в `ЖУРНАЛ_ОШИБОК.md` (рядом с этим пакетом) —
   самоанализ проверяет журнал и предлагает устранение.

## Проверка версии

- Все шесть скилов должны быть актуальными: копии сверены по hash
  (см. `СВОДКА_ХЭШЕЙ.md`).
- Промт v1.1 и скилы обновляются вместе — не бери «половинку».
- Если ты правишь промт — обязательно прогони контрольный набор из
  `01_план\тест_ПРОГОН.md` (6 запросов, порог ≥ 11/12) — правило 19
  скила dev-reflexion.

## Частые вопросы

- **Агент developer не появляется?** После правки конфига перезапусти
  opencode. Промт-файл должен лежать рядом с конфигом в `prompts\dev.txt`,
  иначе `{file:./prompts/dev.txt}` не найдётся — агент просто не создастся.
- **Не хочу агента, люблю вставлять руками** — не добавляй блок `agent`
  в конфиг, а вставь `v1_промт.md` вручную. Всё остальное работает так же.
- **Нет Node.js/npx?** Поставь Node.js LTS с nodejs.org (3 минуты),
  потом перезапусти opencode. Либо не подключай MCP — промт и скилы
  работают без них (dev-comparison/dev-reflexion будут _рекомендовать_
  проверить актуальность вручную).
- **Скил не находится?** Проверь: папка скила должна называться точно
  `dev-registry`, файл внутри — точно `SKILL.md` (заглавные буквы важны).
- **MCP не стартует?** Проверь: пути к exe в `command` существуют;
  для npx-серверов — что npx в PATH (на Windows PowerShell блокирует
  `npx.ps1`, но `cmd /c npx ...` из конфига работает через `npx.cmd`).
- **Хочу без MCP совсем:** удали блок `mcp` из конфига, оставь
  только `skills.paths`. Что-то потеряется: память формул (memory),
  проверка документации (fetch), контроль времени (time).

## Что коллега должен знать дополнительно

- Версии инструментов устаревают: раз в 1–2 месяца проси «проверь
  актуальность» — dev-registry подскажет, что изменилось.
- После 5+ сложных запросов ассистент сам предложит самоанализ
  (это нормально, так задумано в v1.1).
- Пакет проверен: 5 прогонов × 6 контрольных запросов, все ≥ 11/12
  (30/30 ответов, см. `01_план\ОТЧЁТ_ТЕСТ.md`).
