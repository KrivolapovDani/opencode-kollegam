# Пакет «Разработчик v1.1» — для передачи коллегам

**Версия:** v1.1 | **Дата релиза:** 2026-09-20 | **Статус:** проверен, готов к использованию

---

## Что это

Облегчённый системный промт разработчика (v1.1) + 6 dev-скилов + MCP-серверы
для opencode. Агент `developer` работает как универсальный разработчик:
Python, веб (HTML/CSS/JS/TS), PowerShell/автоматизация Windows, Git и CI/CD,
безопасность, обучение программированию, Office-документы (docx/xlsx/pptx).

**Главное отличие от «полного» подхода:** промт стал лёгким (~4–5K токенов),
вся глубина вынесена в скилы, которые подгружаются по требованию.
Качество ответов подтверждено тестами.

**Что нового в v1.1 (анти-деградация):** большие задачи по умолчанию
ТЗ→блоки→цели→журнал; анти-зацикливание; уборка мусора после задач;
ЖУРНАЛ_ОШИБОК.md (фиксация ошибок + проверка в самоанализе); направление
Office-документы (officecli); dev-checks 41→42.

## Установка за 4 шага (кратко)

1. **Скилы** → скопируй `03_скилы\` в `%USERPROFILE%\.config\opencode\skills\`.
2. **Конфиг** → вставь блоки `agent`, `skills.paths` и `mcp` из
   `opencode_developer.jsonc` в свой `opencode.jsonc`, заменив
   `ИМЯ_ПОЛЬЗОВАТЕЛЯ`.
3. **Агент** → перезапусти opencode, переключись на `developer` (Tab).
   Промт подтянется сам из `prompts\dev.txt` — вставлять ничего не нужно.
4. **Проверка** → дай 3 контрольных запроса (список в чек-листе, Шаг 4).

Подробности, частые вопросы и запасной вариант (ручная вставка) —
в `00_ЧЕК_ЛИСТ_УСТАНОВКИ.md`.

## Важно знать

- **Работает только в opencode.** v1.1 без скилов и MCP резко деградирует —
  для других ассистентов добавляй скилы вручную.
- **Память формул** хранится в `memory.jsonl` (настраивается через
  `MEMORY_FILE_PATH`) — не удаляй файл.
- **Работа блоками:** большие результаты ассистент выдаёт частями
  («Часть 1 из N» + чек-поинт). Пиши «продолжи» — он подхватит контекст.
- **Журнал ошибок:** ошибки агента фиксируются в `ЖУРНАЛ_ОШИБОК.md`,
  самоанализ проверяет и предлагает устранение.
- **Регрессия:** после правок промта/скилов прогоняй контрольный набор
  (6 запросов, порог ≥ 11/12) — правило 19 dev-reflexion.
