# Передача проекта коллеге — чек-лист установки

Этот пакет переносит на другую машину готовый результат рефакторинга
промта v5 → v6 + 6 новых скилов + MCP-описания. Всё — за 15–20 минут.

## Что в пакете

```
05_коллегам\
  00_ЧЕК_ЛИСТ_УСТАНОВКИ.md   <- этот файл
  01_ПРОМТ_V6.md             <- облегчённый системный промт (для ручной вставки)
  prompts\v6.txt             <- то же самое, но для автоподключения агентом
  02_Скилы\                   <- 6 папок со SKILL.md
  opencode_config.jsonc       <- готовый конфиг (agent.teacher + mcp)
```

Комплект самодостаточен: промты, скилы, конфиги и документация — в этом
репозитории. Журналы и планы тестирования создаются в текущем проекте
(см. скил self-reflexion).

## Шаг 1. Скопируй скилы (2 минуты)

1. Скопируй папку `02_Скилы\` целиком в глобальную папку opencode:
   `%USERPROFILE%\.config\opencode\skills\`
   (тогда `skills.paths` в конфиге не нужен / можно не трогать).
2. Итог должен выглядеть так:

   ```
   C:\Users\ИМЯ\.config\opencode\skills\
       norma-rf\SKILL.md
       guardrails-rf\SKILL.md
       lesson-templates\SKILL.md
       metod-comparison\SKILL.md
       quality-checks\SKILL.md
       self-reflexion\SKILL.md
   ```

3. Проверка: запусти opencode и просто напиши «открой скил norma-rf» —
   ассистент должен его распознать.

## Шаг 2. Подключи скилы и MCP в конфиге (10 минут)

1. Открой `opencode.json` / `opencode.jsonc` (создай в корне проекта,
   если его нет).
2. Скопируй блоки `skills.paths` и `mcp` из `opencode_config.jsonc`,
   заменив `ИМЯ_ПОЛЬЗОВАТЕЛЯ` на своё.
3. MCP-серверы:
   - `memory` и `sequential-thinking` — Node.js + npx (уже есть, если
     установлен opencode). Проверка после перезапуска: `/mcp` показывает
     сервер живым.
   - `memory` ПОМНИТ базу формул через файл `memory.jsonl` (переменная
     `MEMORY_FILE_PATH` в конфиге уже прописана). Не удаляй этот файл —
     иначе потеряется история формул между сессиями.
   - `fetch` и `time` — это **Python-пакеты**, в npm их НЕТ. Если нет
     Python/uv — поставь uv одной командой:
     `winget install --id astral-sh.uv -e`, затем
     `uv tool install mcp-server-fetch` и `uv tool install mcp-server-time`
     (поставят exe в `%USERPROFILE%\.local\bin`).
4. `brave-search` по умолчанию ВЫКЛЮЧЕН — требует ключ BRAVE_API_KEY
   (бесплатный тариф). Смотри `02_mcp_готовые\mcp_config.md`.

## ВАЖНО: v6 работает ТОЛЬКО в opencode

Промт v6 — «облегчённый»: нормативка, шаблоны, гвардрайлы живут в скилах,
которые opencode подгружает сам. **Если вставить v6 в другого ассистента
(без скилов и MCP) — качество резко деградирует** (не будет реквизитов
приказов, шаблонов, сравнения). Для других инструментов используй полный
v5 или добавь туда скилы вручную. Проверка работоспособности — Шаг 4.

## Шаг 3. Активируй учителя-агента (1 минута, БЕЗ вставки)

Промт подключается автоматически через агента `teacher` (блок `agent`
в конфиге уже прописан, промт берётся из `prompts\v6.txt`).

1. Положи папку проекта в удобное место (папок не теряй структуру:
   `opencode_config.jsonc` и `prompts\v6.txt` должны лежать рядом).
2. Вставь конфиг в `opencode.json`/`opencode.jsonc` (или глобальный
   `~/.config/opencode/opencode.jsonc`, тогда агент будет во всех проектах).
3. Перезапусти opencode, затем в чате переключись на агента:
   - нажми **Tab** (циклический перебор первичных агентов), либо
   - введи `@teacher` (если настроен как субагент).
4. Проверка: агент должен ответить короткой фразой готовности по протоколу
   v6 (БЛОК 8), не перечисляя функций.

> Ручная вставка остаётся как запасной вариант: если не хочешь агента,
> скопируй содержимое `01_ПРОМТ_V6.md` в системный промт вручную.

## Шаг 4. Проверь (3 минуты)

Дай ассистенту три контрольных запроса:

1. «Составь рабочую программу по математике, 5 класс» — должен
   уточнить данные (часы, УМК, ОВЗ), а не выдумывать (шаблон
   lesson-templates).
2. «Какой метод выбрать для урока природоведения 5 класс, тема
   "Свойства воды"» — должен провести сравнительный анализ
   (metod-comparison), а не дать один ответ.
3. «Доработай промт» — должен запустить самоанализ и авторегенерацию
   (self-reflexion), а не отказать.

Хороший признак: в ответах появляются реквизиты приказов (ФГОС ООО
№287 от 31.05.2021, приказ №551 и т. д.) и пометка о редакции.

## Шаг 5. Проверь работу блоками (2 минуты)

Даже рабочий промт «деградирует» в длинных сессиях. Памятка:

1. Большой результат (программа на год, КТП) — ассистент выдаёт блоками
   «Часть 1 из N ... Часть N из N» и в конце блока пишет чек-поинт
   (что готово / что дальше).
2. Напиши «продолжи» — ассистент должен кратко повторить чек-поинт и
   выдать следующий блок. Если вместо этого он переспрашивает «о чём
   задача?» — контекст не подхвачен: прочитайте Шаблон 5 (lesson-templates).
3. При «заново» (новая сессия) — ассистент восстанавливает состояние из
   памяти (memory MCP). Если история пропала — проверь `memory.jsonl`.
4. В конце длинной задачи прогони «доработай промт» — self-reflexion
   даст самоанализ и подскажет, где сессия просела.

## Проверка версии

- Все шесть скилов должны быть актуальными: копии сверены по hash.
- Промт v6 и скилы обновляются вместе — не бери «половинку».
- Если ты правишь промт — обязательно прогони контрольный набор из
  `01_разбор\тест_ПРОГОН.md` (6 запросов, порог ≥ 11/12) — правило 19
  скила self-reflexion.

## Частые вопросы

- **Агент teacher не появляется?** После правки конфига перезапусти
  opencode. Промт-файл должен лежать рядом с конфигом в `prompts\v6.txt`,
  иначе `{file:./prompts/v6.txt}` не найдётся — aгент просто не создастся.
- **Не хочу агента, люблю вставлять руками** — не добавляй блок `agent`
  в конфиг, а вставь `01_ПРОМТ_V6.md` вручную. Всё остальное работает так же.
- **Нет Node.js/npx?** Поставь Node.js LTS с nodejs.org (3 минуты),
  потом перезапусти opencode. Либо не подключай MCP — промт и скилы
  работают без них (скил self-reflexion будет _рекомендовать_ проверить
  ссылки вручную).
- **Скил не находится?** Проверь: папка скила должна называться точно
  `norma-rf`, файл внутри — точно `SKILL.md` (заглавные буквы важны).
- **MCP не стартует?** Проверь: пути к exe в `command` существуют;
  для npx-серверов — что npx в PATH (на Windows PowerShell блокирует
  `npx.ps1`, но `cmd /c npx ...` из конфига работает через `npx.cmd`).
- **Хочу без MCP совсем:** удали блок `mcp` из конфига, оставь
  только `skills.paths`. Что-то потеряется: память формул (memory),
  проверка ссылок (fetch), контроль сроков (time).
